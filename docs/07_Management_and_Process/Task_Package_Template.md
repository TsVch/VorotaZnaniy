## 🎯 1. Business Goal
*Briefly explain WHY this task is being done from a business or user perspective. What value does it deliver?*
> Example: Allow creators to securely upload PDF documents so they can begin monetizing their content.

## ⚙️ 2. Technical Goal
*Briefly explain WHAT needs to be built technically to achieve the business goal.*
> Example: Implement a NestJS endpoint that validates file metadata, generates a presigned S3 URL, and creates a `PROCESSING` document record in PostgreSQL.

## 📖 3. Context
*Provide necessary background information, current state of the system, or specific scenarios relevant to this task.*
> Example: The frontend will call this endpoint before uploading the file directly to Cloudflare R2. The AI worker will later pick up this record for processing.

## 🔗 4. Related Documents
*List all Blueprint documents that govern this task. Freebuff MUST read and adhere to these.*
- [API Contracts](../03_Architecture_and_Design/API_Contracts.md)
- [Database Design](../03_Architecture_and_Design/Database_Design.md)
- [Security Requirements](../04_Security_and_Access/Security_Requirements.md)
- [Coding Standards](../06_Quality_and_Standards/Coding_Standards.md)

## 📁 5. Files to Create
*List the exact paths of new files that must be created.*
- `backend/src/documents/dto/upload-init.dto.ts`
- `backend/src/documents/__tests__/documents.service.spec.ts`

## 📝 6. Files to Modify
*List the exact paths of existing files that must be updated.*
- `backend/src/documents/documents.controller.ts`
- `backend/src/documents/documents.service.ts`
- `backend/prisma/schema.prisma` (if adding new fields)

## 🛠️ 7. Implementation Requirements
*Step-by-step technical instructions on HOW to implement the solution. Be specific about logic, libraries, and patterns.*
1. Create `UploadInitDto` with `class-validator` decorators for `title`, `file_name`, `file_size`, and `mime_type`.
2. In `DocumentsService`, validate that `mime_type` is strictly `application/pdf`.
3. Use the existing `S3Service` to generate a presigned PUT URL with a 5-minute expiration.
4. Create a new `Document` record in Prisma with `status: 'PROCESSING'`.
5. Return the `document_id` and `upload_url` to the client.

## 🏛️ 8. Architecture Constraints
*Explicit rules from the Blueprint that must not be violated.*
- MUST NOT stream file bytes through the NestJS backend.
- MUST use the shared `S3Service` for URL generation.
- MUST throw `BadRequestException` with code `INVALID_FILE_TYPE` for unsupported formats.
- MUST follow the Modular Monolith structure (no cross-module DB access).

## ✅ 9. Acceptance Criteria (BDD Format)
*The specific, testable conditions that define success for this task.*
- **AC-1: Successful Initialization**
  - **Given** an authenticated creator with a valid workspace
  - **When** they POST valid PDF metadata to `/v1/documents/upload-init`
  - **Then** the system returns `200 OK` with `document_id` and a valid `upload_url`
  - **And** a `Document` record is created in the database with status `PROCESSING`.
- **AC-2: Invalid File Type Rejection**
  - **Given** an authenticated creator
  - **When** they POST metadata with `mime_type: "application/x-executable"`
  - **Then** the system returns `400 Bad Request` with error code `INVALID_FILE_TYPE`
  - **And** no database record is created.

## 🏁 10. Definition of Done
*The global checklist that must be satisfied. (Copy-paste the core items from the DoD document).*
- [ ] Code adheres to [Coding Standards](../06_Quality_and_Standards/Coding_Standards.md) (no `any`, strict typing, proper naming).
- [ ] Unit tests are written and pass with ≥80% coverage for new logic.
- [ ] Integration tests verify database interactions.
- [ ] No hardcoded values or secrets in the code.
- [ ] Self-review completed by Freebuff against this exact template.

## 🧪 11. Testing Requirements
*Specific instructions on what and how to test.*
- Write a unit test for `DocumentsService.uploadInit` mocking the `S3Service` and `PrismaService`.
- Write an integration test that hits the actual `/v1/documents/upload-init` endpoint with a test JWT token.
- Ensure negative test cases cover missing fields and invalid MIME types.

## 🛡️ 12. Security Requirements
*Specific security controls that must be implemented for this task.*
- Input validation must strictly enforce file size limits (e.g., `file_size` <= 500MB).
- The endpoint must be protected by `JwtAuthGuard` and `WorkspaceOwnerGuard`.
- The presigned URL must have a strict `Expires` parameter (300 seconds).

## 🚫 13. Out of Scope
*Explicitly state what should NOT be done in this task to prevent scope creep.*
- Do NOT implement the actual file upload logic (frontend handles direct-to-S3 upload).
- Do NOT implement the AI document parsing (handled by a separate task and the AI Worker).
- Do NOT update the frontend UI yet.

## ⚠️ 14. Risks
*Potential pitfalls or edge cases the implementer should be aware of.*
- Risk: Large `file_size` values could cause integer overflow if not typed correctly in Prisma (use `BigInt` or ensure standard `Int` is sufficient for MVP limits).
- Risk: Race conditions if the frontend calls "upload-complete" before the S3 upload finishes (mitigated by backend verifying file existence or relying on S3 event webhooks in the future).

## 🎁 15. Expected Result
*A clear description of what the CTO expects to see upon submission.*
- A clean, linted NestJS module with passing tests.
- Updated OpenAPI/Swagger documentation reflecting the new endpoint.
- A comment in the PR/submission explicitly confirming all Acceptance Criteria and DoD checklists are met.

## 📌 Key Takeaways for the CTO (Me)

1. **Precision is Power**: The more specific the Task Package, the higher the quality of Freebuff's output. Ambiguity is the enemy of automated implementation.
2. **Enforce the Blueprint**: Every "Architecture Constraint" and "Security Requirement" must be a direct reference to an existing Blueprint document.
3. **Binary Review**: During the review phase, I will literally check off each Acceptance Criterion and DoD item. If one fails, the task is rejected with a precise, actionable explanation.
4. **No Scope Creep**: The "Out of Scope" section is critical to keep Freebuff focused and prevent YAGNI violations.
